# ANOWX 漏洞与补丁管理平台

ANOWX 支持 CMDB 资产、漏洞扫描、补丁验证、变更审批、审计证据和只读智能体报表。漏洞情报可同步 CISA KEV、NVD CVE API 2.0 和 GitHub Advisory Database；单一数据源失败不会回滚其他已成功数据源。

公司智能体仅用于查询和生成可视化报表，配置方法见 [`docs/AI_AGENT_MCP.md`](docs/AI_AGENT_MCP.md)。

ANOWX 已从单文件 HTML 原型调整为可部署的前后端分离工程：

- `frontend/`：React + Vite，负责产品 UI、路由和中英文切换。
- `backend/`：Java 21 + Spring Boot，负责认证、业务流程、扫描任务、漏洞、补丁、安全事件/变更工单、审批、自动化编排和审计。
- PostgreSQL：保存业务数据和流程状态。
- `render.yaml`：Render Blueprint，分别创建前端静态站点、Java API 和 PostgreSQL。

## 直接部署到 Render

1. 把本目录全部上传到 GitHub 仓库根目录，隐藏文件 `.gitignore` 和 `.dockerignore` 也要上传。
2. 在 Render 选择 **New > Blueprint**，连接该 GitHub 仓库；已有 Blueprint 时选择 **Manual Sync / Sync Blueprint**。
3. Render 会读取根目录的 `render.yaml`，管理：
   - `gazellio-web`：React 静态站点，由 Render CDN 托管。
   - `gazellio`：现有同名服务就地转为纯 Java API，只使用 `backend/` 作为构建根目录。
   - `gazellio-db`：PostgreSQL，原有同名数据库保留数据。
4. 等待 `gazellio-web` 和 `gazellio` 部署完成，以后请打开 `gazellio-web` 的公开地址。

首次同步 Blueprint 时，在 Render 为后端填写 Secret 环境变量 `CMDB_CLIENT_ID` 与 `CMDB_CLIENT_SECRET`。凭据只由 Java 后端读取，不要写入 Git、前端代码或浏览器本地存储。`CMDB_ENABLED=true` 时，后端启动后会通过只读 API 建立本地资产镜像；补丁执行状态和扫描结果仅保存在 ANOWX，不会回写公司 CMDB。

MFA 采用标准 RFC 6238 TOTP。系统管理员可在“用户与角色”中为单个用户启用；用户下次登录时使用 Microsoft Authenticator、Google Authenticator 等应用完成绑定。Render Blueprint 会自动创建 `MFA_ENCRYPTION_KEY`，请不要在已有 MFA 绑定后删除或更换该值。

演示用户均使用初始密码 `Gazellio@123`：`admin`、`security`、`ops`、`appowner`、`approver`。首次登录后可由管理员在“系统设置 > 用户与角色”重置或修改用户密码。

> Render 现在只在 `frontend/` 改动时构建静态站点，只在 `backend/` 改动时重建 Java 镜像。前端会在构建时自动取得 API 域名。根目录 Dockerfile 仅作为兼容的单镜像部署方案，Render 不再使用它。

### 已有 Render 服务升级注意事项

- 不要删除 `gazellio-db`，否则原有数据会丢失。
- 不需要删除原 `gazellio` Web Service；Blueprint 使用同一名称更新它。
- 同步 Blueprint 后会新增 `gazellio-web`，这个地址才是新的系统入口。
- 如果 Render 中存在早期手工创建、但不受 Blueprint 管理的同名服务，先尝试 Blueprint Sync；仅在 Render 明确报同名冲突时删除旧 Web Service，数据库仍不要删除。

### Render 登录与页面检查

- 必须通过 **Blueprint** 首次创建，保证前端、API 与数据库地址自动关联。
- `/actuator/health` 正常但首页是 403，通常表示部署的仍是旧版本；重新部署最新提交。
- 页面刷新后应继续返回 React 页面，包括 `/login`、`/tasks/{id}` 和 `/automation/runs/{id}`。
- CISA KEV 不在应用启动时自动全量同步，避免免费实例首次启动超时；登录后可在漏洞库手动同步，定时同步仍保留。手动同步会优先读取 CISA 官方 JSON，不可用时自动切换至 `cisagov/kev-data` 官方镜像，并在页面返回目录版本与匹配统计。

## 本地运行

有 Docker Compose 时：

```bash
docker compose up --build
```

浏览器打开：`http://localhost:10000`

本地默认账号：

```text
admin
Gazellio@123
```

## 当前产品能力

- 漏洞库：内置 50 条已建立补丁映射的精选演示漏洞，并可完整同步 CISA KEV 目录，不再隐藏暂无补丁的条目。列表使用服务端搜索、筛选和每页 30 条的分页；CISA 未提供 CVSS 时保留为“未评分”，不伪造默认分数。只有明确的 CVE→补丁关系才会显示可用补丁。
- 漏洞清单：以 `资产 + CVE` 去重，同一资产重复扫描不会重复创建相同实例；已关闭漏洞再次命中会重新打开。扫描证据包含任务、策略、资产 CI、采集通道、检测规则、组件版本、软件清单、规则结果、置信度和证据摘要，而不是单一演示文字。
- 风险处置：优先级综合 CVSS、CISA KEV/实际利用、资产重要度、生产环境和公网暴露计算；评分公式可配置、结果可解释，人工调整必须申请并由具有独立权限的人员审批。漏洞豁免不会直接生效，申请人与审批人职责分离，并跟踪截止日期、补偿控制和剩余风险。
- 漏洞扫描：扫描任务、Agent、认证扫描、网络扫描和测试/预生产/生产定向复测；每条扫描记录均可钻取查看目标、进度、结果与关联复测执行。
- 安全事件工单：扫描结果先进入待确认队列；人工确认为有效漏洞后，才按 P1–P4 生成安全事件并跳转到工单详情。工单支持责任人分派、选择适用补丁并下发处置任务，保留模拟 AITSM 同步编号。
- 变更工单：测试补丁、应用验证和复测通过后，由安全事件触发生产变更；变更、审批、处置任务和自动化执行记录可相互钻取。审批驳回后可修订风险评估、实施与回退方案并重新提交，不会形成流程死点。
- 补丁中心：示例补丁覆盖 CVE 映射、适用性、签发者、指纹、校验值、前置条件、已知问题、安装/回退命令、替代关系、发布说明、受影响实例、补丁服务器和部署记录。补丁包可信性与漏洞修复依据分开展示：前者证明包未被篡改，后者按 CVE 展示受影响版本、修复版本、检测规则与验证依据。
- 内网漏洞详情：页面直接呈现内部通告号、风险属性、受影响版本、检测方法、修复建议、临时缓解措施、虚拟补丁建议和内部补丁候选，不依赖访问外网参考链接。
- 补丁日历：同屏展示 P1–P4 修复截止点、变更维护窗口和人工维护的补丁计划；拥有排程权限的用户可新增、编辑、批准、完成或取消计划，业务事件仍可钻取安全事件或变更工单。
- 处置任务：测试补丁、应用验证、漏洞复测、变更审批、预生产验证、生产执行、生产复测与关闭。每个复测节点均可选择自动复测或人工复测；人工方式要求提交通过/不通过及证据说明，不通过会驳回至对应环境的补丁执行节点。
- 发布审批：紧急 / 重大 / 常规 / 标准四类流程；审批属于变更工单，审批通过后进入自动化实施。
- 自动化编排：补丁安装和效果复测使用两套独立模板；复测只校验安装状态、版本标识、漏洞探针、应用健康与证据，不重新下载或安装补丁。拥有模板编辑权限的用户可新建模板、编辑中英文名称和类型、增加/删除/排序节点、配置节点类型与回退点；已产生执行历史的模板删除时会安全停用。
- CMDB 只读对接：按配置项类型分页同步公司 CMDB 数据，保留原始配置项 ID、类型、状态、责任人、IP、网段、环境和系统信息；资产详情实时读取 CMDB 属性与关系拓扑，扫描任务可按 CMDB 类型、网段或单资产发起。同步成功后，演示资产会停用而不是删除，以保护既有关联记录。
- 全量配置项范围：默认同步已通过接口验证的 25 类配置项，包括产品、应用、服务、虚拟机、物理机、K8S Pod、数据库、中间件、Elasticsearch、网络设备、NAS、机房、机柜、子系统和部署单元；可通过 `CMDB_CLASS_KEYS` 调整。
- 网段批量补丁：可使用 CMDB 镜像资产选择多个 IPv4 CIDR，再按环境、资产类型、操作系统、业务服务和 Agent 状态二次筛选；系统会根据已安装产品判断补丁适用性，支持勾选/排除目标、每批资产数、并发数、失败暂停阈值和维护窗口。单目标失败记录错误码和原因，可在最大重试次数内重试；失败率达阈值时自动暂停后续批次。
- 报告追踪：按 7/30/90/180/365 天口径汇总开放/已修复漏洞、有效例外、SLA 逾期、补丁执行、自动化成功率和补丁合规率；责任人积压和重点风险资产可钻取，报表可导出并保存带操作人和统计窗口的历史快照。资产和漏洞清单使用服务端分页，数据量增长时不再全表传输。
- 双语：界面所有产品文案、状态、按钮、弹窗和流程节点共用同一套中英文资源；API 返回的演示资产、业务系统、人员、扫描名称和执行消息也会随语言原生切换；CI 会检查中英文 key 是否缺失。
- 流程引导：详情页始终用紫色突出当前唯一主动作；启动测试或补丁执行后焦点转到“执行轨迹”，进度达到 100% 后自动转为紫色“返回任务”，审批、变更和复测节点遵循同一交互规则。
- 合规控制：集中处理漏洞例外审批、风险评分复核、软件 EOS/EOL 替代计划、SLA 预警与升级，以及监管事件的一小时通知和 14 天 RCA 时限跟踪。顶部告警入口显示未处理数量。
- 审计：扫描、漏洞确认、例外审批、风险评分、任务、审批、补丁执行、回滚、报表快照和关闭均写入审计日志；审计事件通过前序哈希和当前哈希串联，合规页可验证完整性。
- RBAC：用户、角色和权限均由数据库维护；一个用户可同时拥有多个角色，最终权限按角色权限并集计算，登录鉴权、导航、页面按钮、接口校验与审批候选人共用同一结果。权限粒度覆盖漏洞确认/误报/豁免、工单创建/分派/处置、任务执行/复测、补丁登记/同步/排程/部署、自动化控制、报表与审计导出、用户/角色/凭据/账号状态管理等；角色变更在后续请求即时生效。内置人员已转换为真实用户，审批按角色和 `APPROVAL_ACT` 权限动态选人，不再依赖显示姓名硬编码。

## 交互原则

普通业务页面不展示“从扫描到关闭”的说明性流程条，也不放用于解释系统如何工作的提示卡。流程只在真正需要查看流程的地方出现：

- 自动化编排模板 / 执行记录
- 发布审批详情

列表进入详情页；创建、验证、审批等短操作使用聚焦弹窗；扫描和补丁执行等长操作进入可持续查看的任务 / 执行记录。

## Scanner Agent / 外部漏扫接入

Java API 提供 `/api/agent/*` 接口用于 Agent 或第三方漏扫适配器注册、心跳和上传扫描结果。Render 上的内置扫描执行器用于安全演示完整业务闭环，不会主动扫描任意互联网或内网地址。实际落地时，Agent 应部署在目标网络或终端侧，并通过这些 API 回传结果。

注册 Agent 时使用 Render 自动生成的 `AGENT_REGISTRATION_TOKEN`。

## 性能说明

- 列表和详情使用批量关联查询，避免逐行访问数据库；仪表盘统计由数据库聚合并使用 5–15 秒短缓存。
- 前端轮询不会重叠执行，浏览器标签页进入后台后会暂停轮询；接口请求带 15 秒超时，不会永久停留在加载状态。
- JSON、HTML、CSS 和 JavaScript 响应启用压缩；常用查询字段会由 Hibernate 在 PostgreSQL 中补建索引。
- 自动化测试会用完整演示数据检查常用暖机接口是否在 1 秒内完成。

Render 免费 Web Service 会在空闲时休眠。休眠后的第一次访问需要等待实例重新启动，这段时间不属于应用接口耗时，无法仅靠代码保证 1 秒；如需任何时间打开都快速响应，应使用 Render 常驻实例。

前端静态站点不会休眠，页面资源可以由 CDN 快速打开；免费 Java API 休眠后的第一次登录或数据请求仍需要等待后端唤醒。

## 生产上线前建议

当前工程可以直接用于 Render 演示和 POC。正式生产前建议关闭演示数据、接入企业 SSO/LDAP、替换真实漏扫引擎与补丁源、限制 API 网络入口、配置数据库备份，并按组织实际角色调整审批模板。
